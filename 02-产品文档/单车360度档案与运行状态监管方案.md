## 1. 背景与目标

现有系统已具备车辆建档、资产台账、车型、标签、调度、BOM、售后维保及变更日志等能力，主要解决车辆静态信息和业务流程管理问题。后续接入车载终端、自动驾驶平台、售后系统等数据后，用户需要以一辆车为入口，同时了解其资产归属、当前运行状态、异常处置和历史过程。

本方案的目标是将现有“车辆资产详情页”演进为“单车360度档案”，并新增运行状态与生命周期能力：

1. 一眼判断车辆当前是否可用、是否异常，以及不可用或受限的原因。
2. 从同一页面查看该车的资产、调度、维保、部件、实时运行与历史事件。
3. 对自动驾驶环卫机器人，支持自动驾驶、作业设备、任务和安全状态的展示与追溯。
4. 不重复建设外部运营系统已有的任务、路线、视频或遥测明细能力；仅在车辆管理确有管理需求时，通过接口接入车辆关联的摘要、关键状态、异常和跳转入口。

## 2. 产品定位与边界

### 2.1 产品定位

单车360度档案是以“车辆”为唯一主线的统一查看和处置入口，不替代各专业系统：

```text
资产台账 / 监控中心 / 调度记录 / 维保工单 / 告警列表
                         │
                         ▼
                 单车360度档案
      ┌──────────┬──────────┬──────────┬──────────┐
      │资产与身份 │运行与状态 │处置与任务 │历史与追溯 │
      └──────────┴──────────┴──────────┴──────────┘
```

监控中心解决“多车当前如何运营”；单车360度档案解决“这辆车为何处于当前状态、相关信息与历史是什么”。资产管理、调度、维保、合规等模块仍承担各自的业务操作和规则管理。

### 2.2 数据边界与接入原则

| 数据类别 | 系统内定位 | 来源及处理原则 |
| --- | --- | --- |
| 车辆主数据、资产归属、业务状态 | 车辆管理系统主数据 | 本系统维护并保留完整变更记录 |
| 调度、维保、合规等业务单据 | 关联业务数据 | 以本系统或对应专业系统的业务规则为准，详情页展示关联摘要与入口 |
| 实时位置、在线状态、设备遥测、告警 | 运行状态数据 | 从车载终端/IoT/自动驾驶平台接入；保存当前快照和需要追溯的关键事件 |
| 路线执行、作业面积、能耗、补给次数等任务数据 | 外部运营系统的专业数据 | 外部系统已有时不重复建设；仅在单车状态判断、运营复盘或考核确有需要时，接入任务摘要、关键指标、异常事件及原系统跳转入口 |
| 原始高频遥测、完整视频、逐秒轨迹 | 专业平台原始数据 | 不进入生命周期时间线；通过摘要、统计或外链按需查看 |

**数据接入准入规则：** 每项拟接入数据须同时明确其管理问题、数据来源、刷新频率、责任方、展示位置和触发动作。不能支持状态判断、异常处置、审计追溯或已确认经营指标的数据，不纳入本系统。

## 3. 单车详情信息架构

### 3.1 页面总体结构

```text
┌──────────────────────────────────────────────────────────────────────┐
│ 车辆身份：车牌/VIN/车辆编号/车型版本/归属项目/资产来源/标签             │
├──────────────────────────────────────────────────────────────────────┤
│ 车辆总览 | 运行监控 | 车辆档案 | 业务记录 | 生命周期 | 变更日志 │
└──────────────────────────────────────────────────────────────────────┘
```

1. **车辆身份头部**：固定展示车辆名称/车牌、VIN、车辆编号、车型及版本、归属项目、资产来源和标签。
2. **车辆总览**：默认Tab，以当班决策为目的，聚合作业可用性、实时运行、当班保障、健康与损耗、合规风险及待办提醒；摘要仅展示能支撑状态判断和处置的信息。
3. **运行监控**：承接实时位置、设备状态、告警和趋势等动态数据。本期只提供待接入占位入口，不展示模拟实时数据。
4. **车辆档案**：原“基础信息”，沿用车辆、归属、财务属性、车型配置、硬件/软件配置和车辆标签。
5. **业务记录**：以二级Tab汇总调度信息、售后维保、BOM清单、合规与风险、费用信息；BOM仅自研车辆显示，合规与风险、费用信息本期仅保留未开放入口。
6. **生命周期**：展示业务与运行中的关键事件，不替代原始操作日志。
7. **变更日志**：保留字段级修改和操作审计，面向管理员和追责场景。

**页面展示约束：** Tab标签区上方不单独展示状态总览或概要数据条。作业可用性、运行状态、健康告警、当班保障、数据来源及更新时间集中放入“车辆总览”；历史关键事件放入“生命周期”，避免在各Tab顶部重复占用空间。

### 3.2 适用性原则

不同车辆的详情页采用“统一结构 + 能力动态展示”。例如，普通机动车可展示里程、油量/电量和故障；自动驾驶环卫机器人可展示作业模式、清水量、垃圾箱满载度和自动驾驶健康度。未接入或不适用的指标不显示空字段。

## 4. 状态总览与核心指标体系

### 4.1 状态总览应回答的问题

1. 车辆现在是否可用、是否可调度或可自主作业？
2. 当前处于什么业务与运行状态？
3. 存在哪些影响安全、任务或运维的异常？
4. 谁正在使用或处理该车，下一步应执行什么动作？
5. 当前信息是否足够新鲜、数据来自哪个系统？

### 4.2 指标体系

| 层级   | 指标        | 展示内容                              | 说明                 |
| ---- | --------- | --------------------------------- | ------------------ |
| 一级结论 | 车辆/作业可用性  | 可用、受限可用、不可用、状态未知                  | 页面最醒目的主状态，由规则计算    |
| 业务状态 | 资产生命周期状态  | 待分配、正常使用、调度中、维修中、保养中、待报废、已报废、已处置等 | 由业务流程确认，不被设备上报直接覆盖 |
| 运行状态 | 设备连接与位置   | 在线/离线、当前位置、作业/行驶/停放、最后上报时间        | 来自车载终端或运营平台        |
| 健康状态 | 故障与预警     | 严重故障、一般故障、预警、健康；支持查看原因和处理进度       | 来自设备诊断、告警与工单       |
| 任务状态 | 当前任务与处置   | 当前项目、调度任务、维修/保养工单、责任人             | 来自调度、售后或运营系统       |
| 资源状态 | 车辆可持续运行能力 | 电量/油量、里程、清水、垃圾箱、耗材等               | 按车型、设备能力和已接入数据动态展示 |
| 数据状态 | 数据可信度     | 数据来源、最后更新时间、是否超时、接口异常             | 防止将失效数据误判为实时状态     |

### 4.3 可用性判定规则

可用性是“当前运营结论”，不是新的人工维护字段。规则须可配置，并记录命中原因。

```text
已退出/已报废/已处置
        └─> 不可用：终态车辆

维修中/保养中/存在严重安全故障
        └─> 不可用：等待业务或故障处置

设备离线、数据超时、未接入关键设备
        └─> 状态未知：不能确认是否可用

一般故障、资源不足、进行中调度或受限任务
        └─> 受限可用：必须展示限制原因

其余满足业务、设备与安全条件的车辆
        └─> 可用
```

规则优先级由高到低为：退出终态、业务禁用、严重安全风险、数据可信度、任务限制、资源阈值、正常可用。阈值（如低电量、数据超时、满载）按车型和运营策略配置。

### 4.4 状态展示规范

以下状态信息用于“车辆概览”Tab内的运行与健康摘要，不在Tab标签区上方单独展示：

```text
┌──────────────────────────────────────────────────────────────┐
│ 作业可用性：受限可用                                           │
│ 原因：剩余电量低于阈值；存在1条一般故障                         │
├──────────────────────────────────────────────────────────────┤
│ 业务：正常使用  运行：在线/作业中  健康：一般预警               │
│ 位置：XX路段     最后上报：14:32:08  当前任务：无               │
│ 待处理：故障1项 | 保养3天后到期 | 当前无工单                    │
└──────────────────────────────────────────────────────────────┘
```

颜色仅作为辅助：可用为绿色、受限为黄色、不可用为红色、未知为灰色、业务流转为蓝色。所有颜色必须同时提供文字状态、命中原因、数据来源和更新时间。点击任一状态可进入对应告警、任务、工单或生命周期事件。

### 4.5 业务状态与实时状态的联动边界

实时故障、低电量或离线可改变“可用性”并创建待办，但不得直接修改“维修中”“保养中”等业务状态。业务状态仅由人工确认、调度流程、维修/保养工单或已定义的审批规则变更，从而保持资产、调度与审计口径一致。

## 5. 生命周期记录详细设计

### 5.1 定位与原则

生命周期记录是面向业务的车辆事件档案，用于回答车辆从建档到当前经历了什么、状态为何变化、由谁处理、证据在哪里。它不同于变更日志：

| 对比项 | 生命周期记录 | 变更日志 |
| --- | --- | --- |
| 面向对象 | 运营、管理、复盘人员 | 管理员、审计人员 |
| 记录粒度 | 关键业务、运行和处置事件 | 字段修改及操作明细 |
| 阅读方式 | 阶段与时间线 | 表格或字段级日志 |
| 原始高频数据 | 不直接写入，仅沉淀关键事件 | 不适用 |
| 关联动作 | 进入调度单、工单、告警、外部系统详情 | 查看修改前后值和操作者 |

### 5.2 生命周期阶段与事件类型

| 阶段    | 典型事件                           |
| ----- | ------------------------------ |
| 建档与入池 | 建档、导入、VIN校验、资产入池、车型绑定、设备激活     |
| 资产与归属 | 项目分配/回收、资产属性调整、标签变更、关键资料变更     |
| 调度流转  | 调度申请、审批、出库、交接、任务完成/关闭、流转项目变化   |
| 运行与异常 | 严重故障首次发生/解除、连续离线、关键资源不足、异常任务中断 |
| 维保与部件 | 工单创建、送修、维修完成、保养执行、部件更换、质保变化    |
| 合规与风险 | 保险、年检、证照、违章、事故、理赔、到期处置         |
| 退出与归档 | 报废申请、审批、处置、车辆归档                |

### 5.3 事件记录字段

| 字段 | 说明 |
| --- | --- |
| 事件编号 | 全局唯一，支持外部系统幂等关联 |
| 发生时间 / 记录时间 | 区分实际发生时间和补录/同步时间 |
| 事件类型 / 所属阶段 / 影响等级 | 支持分类筛选和重要性判断 |
| 车辆标识 | 车辆编号、VIN或设备唯一标识 |
| 状态前后值 | 适用于状态、归属、任务和处置结果变化 |
| 责任主体 | 操作人、所属项目、服务商、外部系统或设备 |
| 关联对象 | 调度单、工单、告警、部件、附件、外部单号或跳转地址 |
| 处理结果 | 已确认、处理中、已解除、已关闭等 |
| 数据来源 | 人工操作、车辆管理系统、售后系统、IoT平台、自动驾驶平台等 |
| 证据与备注 | 照片、单据、审批意见、维修说明及必要描述 |

### 5.4 高频数据沉淀规则

位置、传感器、视频和逐秒遥测不直接进入生命周期。系统只沉淀以下可管理、可追溯的事件：

1. 达到或解除严重告警阈值。
2. 连续离线、定位失效、设备故障等超过已配置时长。
3. 调度、维修、保养、合规等业务流程状态变化。
4. 经确认需要复盘的任务异常、人工干预或安全事件。
5. 外部运营系统推送的任务摘要，仅在其与车辆可用性、异常处置、经营考核或已确认管理指标相关时接入。

### 5.5 页面交互

```text
生命周期阶段： 建档 ─ 入池 ─ 分配 ─ 运行 ─ 维保 ─ 退出
                已完成   已完成   已完成   当前     未进入   未进入

筛选： [全部] [资产] [调度] [运行异常] [维保] [合规] [退出]

2026-09-02 14:20  运行异常 / 一般
剩余电量低于阈值，车辆可用性由“可用”变为“受限可用”
来源：车载终端  处理状态：待确认  [查看告警] [发起工单]

2026-08-29 09:15  调度完成
调度单完成，车辆由B项目交接至A项目
操作人：张三  [查看调度详情]

2026-08-12 16:40  保养完成
完成常规保养，更换空气滤芯
来源：售后系统  [查看工单] [查看部件变更]
```

车辆概览中的每个状态结论应可定位到产生该结论的生命周期事件；例如点击“维修中”打开关联维修工单，点击“受限可用”查看最近告警、处理进度和预计恢复时间。

## 6. 自动驾驶环卫机器人适配

### 6.1 适配原则

自动驾驶环卫机器人除机动车共性能力外，还需管理自动驾驶系统、环卫作业设备、作业任务与安全处置。仍遵循“车辆为中心、按需接入”的原则：任务平台已有的数据不重复建设，车辆管理系统只承载影响车辆状态、处置、全生命周期或已确认管理指标的内容。

### 6.2 新增状态指标

| 状态域     | 指标示例                            | 对可用性的影响                |
| ------- | ------------------------------- | ---------------------- |
| 自动驾驶能力  | 自动/人工/远程接管模式、系统就绪、自检结果、当前接管人    | 未就绪、远程接管或关键能力失效时不可自主作业 |
| 安全状态    | 急停、碰撞/近碰、定位可信度、感知与关键传感器健康度、电子围栏 | 急停、碰撞、定位不可用、越界等直接影响可用性 |
| 作业任务    | 当前清扫任务、作业区域、进度、任务结果             | 用于说明当前占用和任务限制          |
| 环卫作业设备  | 清水、污水、垃圾箱、边刷、清扫盘、风机、喷淋状态        | 资源不足或设备故障时受限或不可作业      |
| 能源与补给   | 电量、充电状态、预计续航、补水/卸垃圾需求           | 决定是否可完成当前或下一任务         |
| 连接与远程运维 | 网络质量、远程链路、日志上报、视频状态             | 数据异常时影响状态可信度和远程处置能力    |
| 软件与地图   | 自动驾驶软件、地图、策略配置、OTA状态            | 版本不兼容或升级异常时需限制作业       |

### 6.3 自动驾驶关键事件

除通用生命周期事件外，机器人可增加：设备激活、传感器标定、自动/人工模式切换、远程接管、急停、路线偏离、电子围栏越界、定位异常、关键传感器故障、软件OTA、地图更新、补水、卸垃圾、充电、回库和任务异常结束。

若外部作业平台提供任务数据，单车详情最多展示任务名称、状态、开始/结束时间、进度、异常结论和外部详情入口。作业路线、作业面积、能耗、补给次数、异常次数、人工接管次数、任务结果等数据，仅在满足本方案第2.2节的数据接入准入规则后接入任务摘要或生命周期事件。

### 6.4 高风险操作控制

远程控制、急停、模式切换等高风险能力不作为普通详情页按钮直接开放。后续如需接入，必须具备独立权限、二次确认、操作理由、设备回执、失败兜底、完整审计和实时状态校验；本期仅展示相关状态与处置入口。

## 7. 数据与权限要求

### 7.1 最小数据模型

```text
车辆主数据
  ├─ 资产与归属
  ├─ 当前业务状态
  ├─ 当前运行状态快照
  ├─ 当前告警与待办
  ├─ 关联调度/维保/合规单据
  ├─ 生命周期事件
  ├─ 自动驾驶与作业设备配置（按车型适用）
  └─ 外部系统关联标识与跳转入口
```

### 7.2 权限原则

1. 车辆范围仍遵循管理员、项目经理、财务、管理层、车队人员的既有项目与角色数据权限。
2. 实时位置、视频、远程处置、自动驾驶安全信息按更高权限控制，并记录访问和操作审计。
3. 生命周期事件默认只读；修改、补录、撤销需记录原因、操作者和前后值。
4. 外部系统数据按来源标识展示；接口延迟或失败时明确显示数据新鲜度，不能将历史快照伪装为实时数据。

## 8. 建设范围与实施优先级

| 阶段 | 范围 | 产出 |
| --- | --- | --- |
| 第一阶段 | 单车详情框架、车辆概览状态摘要、可用性规则、基础生命周期事件、调度/维保/BOM/变更日志整合 | 可从车辆台账进入单车360度档案，判断状态并追溯关键业务事件 |
| 第二阶段 | 接入车载终端/IoT状态、告警、位置和数据新鲜度；监控中心跳转单车详情 | 支持实时运行状态与异常处置闭环 |
| 第三阶段 | 自动驾驶环卫机器人适配、作业平台按需集成、自动驾驶安全与设备健康事件 | 支持机器人作业可用性和关键过程追溯 |
| 第四阶段 | 合规、风险、费用、退出等生命周期域接入 | 形成完整车辆生命周期档案 |

## 9. 待确认项

1. “可用性”是否同时服务于调度决策；不同车型、项目和任务的阈值及规则由谁维护。
2. 车载终端、IoT平台、自动驾驶平台和作业平台的现有接口、设备唯一标识和数据质量情况。
3. 哪些外部任务数据确实需要进入本系统，分别用于状态判断、运营复盘、经营考核还是仅作为跳转查看。
4. 自动驾驶机器人涉及的急停、远程接管、视频、位置等数据的可见范围和操作权限。
5. 生命周期事件的保留期限、附件存储位置、外部单据跳转方式及补录责任人。

## 10. 验收标准

1. 用户可从资产台账、监控中心、调度和告警入口进入同一车辆的单车360度档案。
2. 页面顶部可在一次浏览中展示可用性、业务状态、运行状态、健康状态、当前任务/工单、数据更新时间和待办数量。
3. 每个“受限可用”“不可用”或“状态未知”结论均有可查看的原因、来源和关联处理入口。
4. 实时状态变化不直接覆盖需业务确认的资产状态；状态变化过程可追溯。
5. 生命周期记录可按阶段、类型、时间、来源和严重程度筛选，并可跳转关联单据或外部系统详情。
6. 高频遥测不直接堆入时间线，关键异常和已确认管理事件可正确沉淀。
7. 自动驾驶环卫机器人仅展示其适用且已接入的自动驾驶、作业设备和任务摘要指标；外部系统已有的任务明细不重复建设。
