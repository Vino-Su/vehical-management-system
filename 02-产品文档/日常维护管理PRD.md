## 1. 业务背景与使用角色
### 1.1 业务背景
环卫车辆的日常状态影响作业质量与项目交付。车辆管理系统统一制定各车型维护标准、周期和生效范围，按规则产生任务；城市管家小程序由项目人员执行并回传结果。PC端提供计划配置与任务追溯，减少漏检、标准不一致和维护风险积累。
### 1.2 使用角色
| 角色 | 职责 | 客户端 / 权限范围 |
| --- | --- | --- |
| 有计划维护权限的管理人员 | 查询、新增及保存草稿、编辑、启用、停用、删除计划，维护检查项与执行规则 | PC；操作范围沿用系统授权，具体角色名称和授权矩阵由现有权限体系配置 |
| 有任务查看权限的管理人员 | 查询任务、查看检查结果 | PC；仅授权范围内数据 |
| 项目经理、安全员 | 接收并执行维护任务 | 城市管家；原文明确的接收角色，小程序页面另期设计 |

### 1.3 核心目标与价值
| 目标 | 成功结果 |
| --- | --- |
| 标准统一 | 按车型建立系统－部件－检查项目－判定标准，完整维护具体周期 |
| 周期准确 | 区分自然日日检与按完成日期滚动的非日检，跨周期任务独立 |
| 范围明确 | 支持全部项目或指定项目，以及车辆状态、无作业任务的豁免 |
| 执行可追溯 | PC可追溯车辆、计划、周期、任务状态和检查结果 |

## 3. 功能详细设计
### 3.1 F01 维护计划管理
#### 3.1.1 功能目标与范围
管理人员按车型统一维护检查计划；保存后可查看完整检查项和执行规则，任务按所配周期执行。
#### 3.1.2 使用条件与权限
查询与详情需查看权限；新增、保存草稿、编辑、启停、删除需计划维护权限。真实权限及项目授权由服务端控制，原型仅展示操作流程。
#### 3.1.3 数据与字段规则
| 字段 / 条件 | 说明 | 校验或匹配 |
| --- | --- | --- |
| 计划名称 | 用户输入 | 必填，去除首尾空白；查询支持包含匹配 |
| 适用车型名称 | 引用车型主数据 | 必选；查询精确匹配 |
| 适用项目 | 全部项目或指定项目集合 | 指定项目时至少选一个；查询命中指定项目或全部项目计划 |
| 包含周期 | 由检查项的具体周期汇总 | 不由用户单独维护；查询命中至少一个该周期检查项 |
| 检查项数 | 当前计划检查项总数 | 不随查询周期缩减计数 |
| 计划状态 | 枚举值：草稿（新增暂存）、启用（按生效时间执行）、停用（不生成新任务） | 支持精确查询；草稿需先完善并正常保存 |
| 生效时间 | 启用时选择立即生效 / 次日生效，默认次日 | 统一北京时间；次日指次日00:00；时间未到时标明待生效，查询归入启用 |
| 备注 | 补充计划说明 | 可空 |
| 创建 / 更新信息 | 创建人、创建时间、更新人、更新时间 | 系统记录、只读 |
| 计划台账展示字段 | 计划名称、适用车型、包含周期、计划状态、创建时间、创建人、更新时间、更新人、生效时间及操作 | 适用项目、检查项数不作为列表展示列；生效时间独立展示，草稿/停用或缺失值显示“—”，未来时间保留待生效提示 |

#### 3.1.4 业务规则与状态变化
1. 一个计划可包含多个具体周期，不同周期分别生成任务。
2. 同车型、项目范围相交且包含相同具体周期的启用计划构成冲突；启用和编辑启用计划保存时阻断并指出冲突计划及周期。已安排次日生效的启用计划也占用对应范围；草稿、停用计划不占用范围。不同具体周期允许同时生效且不合并。全部项目与任一指定项目视为范围相交。
3. 正常保存使用完整字段和检查项校验；新增正常保存后为停用，需单独启用。编辑不提供另存草稿，启用或停用计划保存后保留状态及已有生效时间；编辑草稿并正常保存后转为停用。未保存修改不影响正式数据，取消编辑时提示放弃修改。
4. 删除需二次确认；取消不改变数据；确认后移除计划并刷新台账。已生成任务保留生成时快照，不因计划修改或删除重写历史。
5. 仅新增可保存草稿，只要求计划名称非空；车型、项目、检查项和判定标准允许暂缺，不做启用冲突校验。成功后持久保存已有输入并进入草稿详情，不生成任务；再次进入可继续完善，但编辑页不再提供保存草稿。草稿允许查看和删除。
6. 停用计划启用前重新执行完整校验及冲突校验；确认生效时间后才更新状态。取消启用不改变数据；校验或存储失败保留原状态与选择并展示原因。
7. 停用立即生效，需二次确认；停止生成新任务，取消尚未到时的生效安排；已有任务继续沿用其执行规则，历史结果和快照保留。再次启用须重新选择生效时间并校验。
#### 3.1.5 交互流程
1. 进入计划台账 → 按名称、车型、项目、具体周期、计划状态组合查询 → 查看分页结果；重置恢复全部计划，启用计划同时展示生效时间及待生效提示。
2. 新增 → 录入基础信息 → 可保存草稿，或补齐检查项及规则后正常保存。草稿保存只校验名称，正常保存完整校验；通过则进入详情并提示成功，失败展示原因并保留输入。
3. 详情 → 编辑 → 修改并保存 → 返回更新后的详情。取消需确认放弃修改。
4. 台账删除 → 确认计划名称 → 确认后删除；取消保留原数据。结果为空时提示调整条件或新增计划。
5. 计划详情在名称后展示计划状态标签，副标题只展示适用车型与检查项数；移除顶部清单来源、周期数量、待补充数量和启停说明，标题区之后直接展示两个分区入口。首个分区为“基本信息与执行规则”，进入时默认展示；第二个分区为“维护项目”。基本信息分别展示创建人、创建时间、更新人、更新时间。新增、编辑与详情统一分区顺序并默认展示基本信息与执行规则，概要均展示适用车型与检查项数；适用项目归入基本信息，编辑展示已有计划状态。切换分区保留未保存内容，所有检查项和规则统一保存。
6. 草稿 → 继续完善 → 正常保存完整校验 → 转为停用；停用 → 启用 → 选择立即或次日生效 → 确认并重新校验 → 更新状态与生效时间。启用 → 停用 → 二次确认 → 停止新任务生成；取消操作保持原状态。
#### 3.1.6 异常处理
正常保存时必填缺失、无检查项、未指定项目、应校验的周期冲突或保存失败均阻止成功反馈并保留输入；草稿保存只校验名称且仅限新增；校验失败时展示原因，切换到错误所属分区，并定位缺失字段或检查项。不存在的计划显示未找到及返回入口，不自动显示另一计划。
#### 3.1.7 外部依赖
车型、项目、当前用户及权限来自对应主数据和权限模块。
### 3.2 F02 检查标准与周期配置
#### 3.2.1 功能目标与范围
按“系统 → 部件 → 项目”组织检查标准，支持按具体周期查看、单项编辑及批量配置周期。
#### 3.2.3 数据与字段规则
| 字段 | 规则 |
| --- | --- |
| 所属系统 | 必填；枚举值：底盘系统、三轮线控底盘、边刷系统、滚刷系统、水路系统、电气系统、白车身系统、照明系统、自动驾驶系统、整车、侧抽式换电系统；保留来源清单中的独立系统分类 |
| 检查部件 | 必填，自主输入 |
| 检查项目 | 必填，支持自主新增 |
| 判定标准 | 必填，描述正常检查结果的判断依据 |
| 检查周期 | 必填；枚举值：日（日例保）、两日（短维保）、周（短维保）、季度（中维保）、半年（长维保）、年（长维保） |
| 清单附属资料 | 来源存在时保留序号、件号、版本、不符合标准处置措施、新增配套工具、检查方法与备注；可查看资料和已有方法文档，不以推测内容填补原文空白 |

#### 3.2.4 业务规则与状态变化
切换周期只改变查看范围，不修改数据。同计划中系统、部件（来源提供件号、版本时共同用于区分部件）、项目和具体周期均相同的重复项应提示并阻止保存，不合并名称相同但件号或版本不同的来源条目。批量调整仅作用于当前勾选项；展示当前累计勾选数量，切换周期或应用其他筛选条件时清空勾选，避免误改隐藏项。全选仅覆盖当前筛选结果中已展开的检查项，折叠分组不取消已有勾选，可主动清空选择。检查项修改在整份计划保存后生效；删除检查项需确认。
#### 3.2.5 交互流程
1. 计划新增/编辑 → 新增检查项 → 填写五个字段 → 校验后加入计划待保存内容。
2. 点击检查项编辑 → 回显 → 校验后更新；取消不修改。
3. 勾选检查项 → 选择目标周期 → 批量应用 → 刷新周期计数；没有勾选时提示先选择。
4. 切换全部/具体周期 → 按系统分组查看该范围；无检查项时显示空态。
5. 可组合按所属系统、部件/检查项目/件号关键词及“仅看待补充”查询，结果按系统组织；新增、编辑与详情均不分页，一次展示当前条件下全部检查项；重置恢复全部周期与全部项目。
6. 新增、编辑与详情均支持折叠、展开当前筛选结果的全部系统分组；浏览长列表时可持续访问筛选、批量操作、列标题和保存入口。
#### 3.2.6 异常处理
字段为空或重复时保留表单并提示；至少保留一个有效检查项才允许保存计划。批量调整导致重复或计划周期冲突时，阻断整份计划保存并提示修正。
### 3.3 F03 计划执行规则
#### 3.3.1 功能目标与范围
配置计划生效范围、豁免条件和日检模式，明确首次起算依据。
#### 3.3.3 数据与字段规则
| 字段 | 规则 |
| --- | --- |
| 生效范围 | 全部项目 / 指定项目；指定项目支持多选 |
| 可配置豁免状态 | 在库－保养中、在库－维修中、在库－待报废、待分配、调拨中；现有资产字段“在库-维修”映射为“在库－维修中”，不新增一套资产状态 |
| 固定排除状态 | 已报废、已处置始终不生成任务，不允许取消排除 |
| 无作业任务车辆豁免 | 仅影响日例保；其他具体周期不适用 |
| 日检模式 | 勾选出车前检查，则日例保每日出车前完成；未勾选时按当日日检执行要求 |
| 首次周期起算依据 | 入项目日期，只读；车辆缺少入项目日期时不能用建档日期替代 |

#### 3.3.5 交互流程
1. 新增/编辑计划 → 选择生效范围及项目 → 勾选豁免、无作业日检豁免和出车前检查。
2. 查看首次起算依据 → 与检查项一起保存；校验成功后在详情显示完整规则，失败保留配置。
#### 3.3.7 外部依赖
依赖车辆当前车型、归属项目、入项目日期、资产状态及作业任务数据。新车首次维护按入项目日期叠加对应周期起算；日检仍按自然日生成。
### 3.4 F04 维护任务查询与结果追溯
#### 3.4.1 功能目标与范围
PC集中查看系统生成的维护任务及小程序回传的检查结果，支持从任务追溯原计划及车辆档案，并可将选中或查询范围内的任务导出为 CSV 用于线下核对。
#### 3.4.3 数据与字段规则
| 字段 / 条件 | 说明 |
| --- | --- |
| 任务编号 | 系统标识，支持包含查询 |
| 网联编号 | 列表展示车辆网联编号；查询支持车牌号、车架号关键词包含匹配、不区分大小写；提供车辆档案入口 |
| 维护计划 / 车型 / 项目 | 任务生成时所属计划和车辆范围；维护计划按任务快照的计划名称包含匹配、不区分大小写，计划删除后仍可按原名称查询；项目支持精确查询 |
| 维保类型 / 具体周期 | 类别由具体周期派生；周期精确查询 |
| 生成时间 / 执行要求 | 开始日00:00生成，支持按开始、结束日期区间筛选（含边界日）；执行要求仅在任务详情展示，出车前日检单独说明 |
| 任务状态 | 待开始、进行中、已完成、逾期、逾期完成、已失效 |
| 接收角色 | 项目经理、安全员；具体执行人员于结果回传后记录 |
| 完成人 / 实际完成时间 | 未完成时显示未完成，无值不填造结果 |
| 检查结果 | 按任务快照展示系统、部件、项目、标准、检查结果及结果说明；未执行显示待检查 |
| 查询区展示 | 复用公共渐进筛选组件：首行常显任务编号、车辆、归属项目；维护计划、检查周期、任务状态、生成时间收在“展开更多”，展开或收起不改变已填条件与已应用结果 |
| 批量选择 | 表头复选框全选仅作用于当前页；单条勾选切换页码后保留并显示累计数量；查询、重置或点击“清空选择”后取消全部勾选；半选状态随当前页勾选情况同步 |
| 导出 | 有勾选时仅导出当前页选中任务；未勾选时二次确认后导出当前查询条件下全部任务；导出字段为任务编号、网联编号、归属项目、维护计划、检查周期、维保类型、生成时间、任务状态、实际完成时间、完成人，不含勾选列与操作列；CSV 含 UTF-8 BOM；文件名可修改，默认“维护任务-YYYY-MM-DD.csv”；无数据不生成空文件 |

#### 3.4.4 业务规则与状态变化
台账组合查询取交集并分页；查询与重置回到首页。任务详情只读，未完成任务不展示已完成结果。计划删除后仍显示任务快照并说明原计划已删除；无效任务编号展示未找到，不能自动跳到其他任务。导出不修改当前勾选状态；选中导出仅限当前页，若已勾选记录均不在当前页则提示先在本页勾选，不做跨页导出；未勾选时导出全部须经二次确认，取消后不生成文件；导出完成后保留查询结果与勾选，便于继续操作。
#### 3.4.5 交互流程
1. 进入任务台账 → 按任务编号、车辆、维护计划、项目、周期、状态及生成时间范围查询 → 查看分页结果。
2. 点击详情 → 查看任务基础信息、执行信息和逐项检查结果。
3. 查看计划 → 进入仍存在的计划详情；点击车辆 → 进入对应车辆档案；返回台账继续查询。
4. 勾选当前页任务或使用表头全选 → 点击“导出” → 核对导出范围与文件名 → 确认导出 CSV；未勾选时先二次确认导出全部查询结果。
5. 点击“清空选择”取消当前全部勾选；查询或重置后勾选自动清空。
#### 3.4.6 异常处理
无匹配结果时显示空态；任务数据读取失败时明确提示，不能用空结果代替失败；未执行、失效任务不提供PC执行入口。导出时当前查询结果为空则提示“当前查询条件下暂无可导出的数据”且不生成文件；已勾选记录均不在当前页时提示先在本页勾选，不执行跨页导出；取消全部导出确认则不生成文件；文件名为空时提示并保持弹窗，不关闭弹窗、不导出。
#### 3.4.7 外部依赖
任务调度服务、小程序结果回传及车辆资产详情。当前静态原型使用任务样例验证查询和结果展示，不声称已接入真实任务和执行结果。

## 4. 业务规则汇总
### 4.1 周期计算
| 具体周期 | 分类 | 持续时间口径 |
| --- | --- | --- |
| 日 | 日例保 | 按自然日逐日生成 |
| 两日 | 短维保 | 自上次同周期实际完成日期满2个自然日 |
| 周 | 短维保 | 自上次同周期实际完成日期满7个自然日 |
| 季度 | 中维保 | 自上次同周期实际完成日期满3个月，不按自然季度首日 |
| 半年 | 长维保 | 自上次同周期实际完成日期满6个月 |
| 年 | 长维保 | 自上次同周期实际完成日期满1年 |

新车无上次同周期完成记录时，以入项目日期作为首次周期基准；不同周期各自计算，不用其他周期的完成时间重置本周期。月末及闰年日期边界见5.3。
### 4.2 任务生成与归集
只有处于启用状态且已到生效时间的计划参与任务生成；符合车型、项目范围且未被豁免的车辆，常规任务在开始日00:00生成。选择立即生效时，在确认时检查当前到期任务，仍按原周期基准计算，不重置入项目日期或上次完成日期、不补发往日任务。同一车辆、同一具体周期、同轮到期的检查项汇总为一个维护任务；不同具体周期分别生成、分别执行，不合并成一张任务。任务不得因重复启用或调度重试而重复生成。
### 4.3 执行时限与状态
| 场景 | 规则 |
| --- | --- |
| 出车前日例保 | 每日出车前完成 |
| 其他检查 | 在所属周期内的00:00－24:00执行；任务展示对应执行要求 |
| 日例保到期未完成 | 变为已失效，不可再次执行 |
| 非日例保到期未完成 | 变为逾期；逾期期间支持小程序继续执行 |
| 下一同周期新任务生成 | 原逾期任务的可执行保留期截止；PC保留历史记录供追溯，不继续开放旧任务执行 |
| 实际完成 | 保存实际完成日期；用于下一同周期任务的滚动计算 |

原文未给出非日检执行窗口的精确截止算法，以及长期不完成时下一新任务的调度策略，见5.3；本期不以静态页面虚构自动状态流转。
### 4.4 数据安全与一致性
保存成功后才更新正式数据；失败保留输入并提示。用户输入按文本显示。计划修改不覆盖历史任务快照，删除不连带删除历史任务。服务端应按授权控制项目与操作权限；公共导航的项目选择在现阶段仅记忆查看范围，业务查询以页面条件为准。
