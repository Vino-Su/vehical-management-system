## 2 背景与目标

车辆资产详情页以单台车辆为主线承载车辆档案、业务记录和生命周期信息。车辆总览直接展示电量、资源、运行和健康等关键状态数值，并承担可用性判断和处置入口；运行监控进一步提供位置、遥测、系统诊断、趋势和原始记录，用于解释状态原因和完成单车问题定位。

运行监控Tab用于提供单车级实时运行工作台，帮助用户：

1. 查看当前车辆的位置、在线状态和数据新鲜度。
2. 了解车辆当前的驾驶状态、运行状态、补给状态、速度、资源和任务状态。
3. 查看已有故障与异常记录，识别需要进一步核查的问题。
4. 查看当前故障、异常和近期趋势，并跳转到故障、异常、工单、生命周期或全局监管页面。
5. 在保持车辆详情上下文的情况下完成单车运行问题定位。

## 3 产品定位与边界

### 3.1 页面定位

运行监控是“单车实时解释与下钻”页面，不是全局车队监管页面，也不是跨车辆运行数据分析报表。

| 页面        | 关注范围     | 核心用途             | 运行监控的关系          |
| --------- | -------- | ---------------- | ---------------- |
| 车辆总览      | 单车汇总     | 判断车辆是否可用、是否需要关注  | 提供结论和入口，不展示遥测明细  |
| 车辆监管一张图   | 多车辆空间态势  | 发现异常、定位车辆、查看整体分布 | 可从本页跳转并定位当前车辆    |
| 车辆运行数据    | 多车辆结构化数据 | 查询、比较、筛选、导出运行记录  | 可从本页带入车辆条件查看完整记录 |
| 车辆详情-运行监控 | 单车实时上下文  | 解释当前状态、查看详情、发起下钻 | 本PRD范围           |

### 3.2 不重复建设的内容

- 不复制车辆总览中的运行总账、车龄、累计费用和完整可用性结论。
- 不重复建设车辆总览已经展示的电量、清水、垃圾箱、速度等关键状态摘要；只有在提供补给、趋势、任务影响等进一步信息时，才在本页展示对应明细。
- 不复制车辆监管一张图的市级聚合、全局筛选和车队统计。
- 不复制车辆运行数据页的跨车辆查询、分页表格、批量勾选和导出能力。
- 不在本页直接开放远程控制、急停、驾驶状态切换等高风险操作。
- 不重复建设外部作业平台已经提供的完整任务、路线、视频或遥测系统，仅展示摘要和跳转入口。

### 3.3 数据展示原则

1. 车辆总览负责直接展示关键状态数值和处置结论；本页只共享必要上下文，并提供更高粒度的实时数据、诊断和解释信息。
2. 指标按车辆能力动态展示；不适用或未接入的指标不显示空字段。
3. 所有实时结论同时展示数据来源和采集时间；数据延迟或失效时不得伪装成实时状态。
4. 实时状态不得直接覆盖车辆档案中的业务状态；业务状态仍由资产、调度、维修或保养流程维护。

## 6 页面结构

页面沿用车辆详情页顶部固定车辆身份信息和一级Tab，不重复绘制车辆身份卡片。

建议内容顺序：

1. **数据状态提示**：数据来源、最后采集时间、当前数据质量和接口状态。
2. **主体双栏区**：左侧位置与轨迹，右侧运行遥测。
3. **资源与补给区**：SOC、剩余水量、垃圾箱状态百分比及补给状态；与总览共享来源和口径。
4. **任务关联区**：任务名称、区域、状态和进度，以及外部平台入口。
5. **趋势区**：里程、故障数量和异常数量等时间序列。
6. **故障与异常记录区**：分别展示两类原始记录，提供对应监管页面入口。

推荐布局为“左侧地图 + 右侧状态，底部趋势与故障/异常记录”。屏幕宽度不足时改为纵向排列，不产生页面级横向溢出。

## 7 功能详细设计

### 7.1 F01/F02 数据状态与运行诊断

车辆总览已经直接展示电量、资源、运行模式、速度、任务和健康等关键状态数值，并承担车辆可用性判断。本页不再重复展示一组实时状态摘要卡，而是展示数据新鲜度以及用于问题定位的运行诊断字段。

| 字段 | 展示要求 |
| --- | --- |
| 数据质量与在线状态 | 由平台连接与数据质量信息提供，和信号强度分开 |
| 数据采集时间 | 格式YYYY-MM-DD HH:mm:ss |
| 数据来源 | 标明车载终端、IoT平台或其他来源；原型数据标明演示 |
| 驾驶状态、信号强度、运行状态、补给状态 | 遵循7.3节统一口径 |
| 车辆速度、档位 | 按终端上报值展示 |
| SOC、剩余水量、垃圾箱状态 | 在资源与补给明细中展示百分比 |
| 当前任务 | 保留独立作业平台提供的任务关联 |

### 7.2 F03 单车位置地图

地图仅服务当前车辆，不复制监管一张图的车队聚合和全局筛选。

- 展示当前车辆点位、车型图标、车头方向和车辆标识。
- 展示当前位置经纬度、可解析地址和定位时间。第一阶段不展示无依据的定位精度、可信度、电子围栏越界结论或精度范围。
- 支持“在监管一张图中定位”跳转，并携带 `vehicleId`、车架号或网联编号。
- 支持查看当前车辆最近一段轨迹；完整日期、起止时间、播放倍速和视频回看复用监管一张图的轨迹回放能力。
- 坐标无效、缺失或已过期时显示位置空态及原因，不绘制误导性点位。

### 7.3 F04 运行遥测

运行遥测字段与《车辆实时监管 PRD》中的车辆运行数据保持一致，但本页仅展示当前车辆的实时快照和有限趋势。

| 序号 | 字段 |
| ---: | --- |
| 1 | 车架号 |
| 2 | 所属项目 |
| 3 | 经度 |
| 4 | 纬度 |
| 5 | 驾驶状态 |
| 6 | 信号强度 |
| 7 | 运行状态 |
| 8 | 补给状态 |
| 9 | 车辆速度 |
| 10 | 档位 |
| 11 | 物联网终端在线状态 |
| 12 | SOC(%) |
| 13 | 剩余水量(%) |
| 14 | 垃圾箱状态(%) |
| 15 | 数据采集时间 |

驾驶状态的枚举值为：自动驾驶、远程驾驶、人工驾驶；运行状态的枚举值为：作业、转场、运维、停靠、关机；补给状态的枚举值为：未补给、充电、加水、换电。
SOC、剩余水量、垃圾箱状态均按百分比展示，有效范围为0%～100%，0%为有效值；缺失、无效或不适用时显示“—”，不得补为0%。信号强度按来源定义展示，不自行换算单位或制定等级阈值。驾驶状态中的远程驾驶以本次确认口径为准，不从AUTO/MANUAL自行推导。

“查看完整运行数据”跳转至 `03-高保真页面/monitor/vehicle-running-data.html`，并带入当前车辆筛选条件。本页不展示跨车辆列表、不提供批量导出。

### 7.4 F05 故障与异常依据
第一阶段不展示自动驾驶就绪、自检、接管人、近碰、传感器在线数、掉线次数、地图版本、OTA和耗材剩余寿命等缺少依据的结论。已有故障、异常记录及对应入口按7.7节保留，不新增诊断规则。
### 7.5 F06/F07 资源与任务
资源与补给明细展示SOC、剩余水量、垃圾箱状态和补给状态，字段规则见7.3节。删除污水量、预计续航和设备在线数量；不将垃圾箱百分比自行解释为满载度或剩余容量。
已有当前任务、区域、状态、进度及外部详情入口继续由作业平台提供，不从车辆运行状态推导任务进度。

### 7.6 F08 趋势分析

支持时间范围：最近1小时、最近24小时、最近7天；默认最近1小时。查询时间范围无数据时显示空状态，不生成虚假折线。

建议趋势：

- 车辆里程：总里程、自动驾驶里程、人工驾驶里程
- 故障数量
- 异常数量

趋势图须显示单位、时间轴、数据来源和采样时间；采样点过密时进行前端聚合，但不得改变异常发生时间。

### 7.7 F09 故障与异常记录

运行监控直接复用系统已采集的“车辆故障信息”和“车辆异常记录”，不新建第三类告警实体，也不将两类记录强行合并。运行监控只展示最近的原始记录和数量，不重新生成总览提醒；默认按各自的上报时间倒序排列，并提供“查看全部”入口跳转至对应监管页面。

#### 7.7.1 故障记录

故障记录用于摘要展示车辆主动上报的软硬件故障码数据，字段语义与《车辆实时监管 PRD》保持一致；完整上报台账中的车型、系统、整车及上装原始等级、平台接收时间在车辆故障信息页查询，本区域继续使用以下摘要字段：

| 字段 | 说明 |
| --- | --- |
| 故障码 | 车辆上报的故障编码，按故障页面的故障码样式展示 |
| 故障定义 | 故障码对应的文字定义，过长时省略并支持查看完整内容 |
| 故障上报时间 | 格式 `YYYY-MM-DD HH:mm:ss`，默认按时间倒序 |

故障记录卡片提供“查看全部故障”入口，跳转 `vehicle-fault-info.html` 并带入当前车辆的车架号、车牌号或网联编号。

#### 7.7.2 异常记录

异常记录用于展示策略规则触发的异常事件，当前异常类型为：超时停靠、超速行驶、限行区行驶。字段与《车辆实时监管 PRD》保持一致：

| 字段 | 说明 |
| --- | --- |
| 异常类型 | 展示策略命中的异常类型 |
| 开始时间 | 异常事件开始时间 |
| 结束时间 | 异常事件结束时间；数据为空时展示“进行中” |
| 持续时长（min） | 展示系统计算的持续分钟数，保留原始精度 |
| 异常上报时间 | 格式 `YYYY-MM-DD HH:mm:ss`，默认按时间倒序 |

异常记录卡片提供“查看全部异常”入口，跳转 `vehicle-anomaly-records.html` 并带入当前车辆的车架号、车牌号或网联编号。

#### 7.7.3 展示与统计规则

- 顶部可展示当前车辆在所选时间范围内的“故障数量”和“异常数量”两个独立统计值；两者不得合并为一个无法解释的“告警数”。
- 故障记录和异常记录分别排序、分页和跳转；同一时间发生的故障与异常可以同时存在，不做去重覆盖。
- 本期不展示严重/一般/提示等级、处理状态、数据来源等字段，除非后端后续为对应记录提供明确字段；前端不得根据故障码或异常类型自行推断等级和处置状态。
- 车辆故障信息页可按原值记录上报的整车故障等级与上装故障等级；原始等级不等同于单条故障严重程度，本区域不额外增加等级及处置操作。台账按次保留上报明细，不能据此推断故障持续或恢复状态。
- 本页不提供故障或异常的编辑、确认、关闭、批量导出操作；完整查询、筛选和导出继续由车辆故障信息页、车辆异常记录页负责。

故障和异常记录属于动态监管数据，不直接写入生命周期时间线；只有后续形成已确认的业务结果或处置事件时，才按生命周期事件规则沉淀。

### 7.9 F11 数据状态与异常态

必须支持以下状态：

- 加载中：显示局部加载状态，不阻塞已经展示的车辆身份信息。
- 正常：显示最新采集时间和数据来源。
- 数据延迟：显示“数据延迟”，保留最近快照并明确快照时间。
- 数据超时：显示“数据已超时”，不得标记为当前在线。
- 接口失败：显示失败原因和重试入口；本期高保真阶段可用静态错误态验证。
- 无数据：按模块显示空状态和缺少的数据来源。
- 部分数据缺失：已接入字段正常展示，缺失字段显示“暂无数据”，不影响其他模块。

## 8 交互规则

1. 从车辆总览点击“查看运行监控”后进入本Tab，并保持当前车辆上下文。
2. 切换车辆详情一级Tab时，当前车辆不变；切换离开运行监控不会清除已选时间范围，重新进入时恢复默认实时快照。
3. 所有跳转操作均在目标页面带入车辆标识，并保留返回车辆详情的路径。
4. 时间趋势查询的开始时间不得晚于结束时间；错误时不发起查询并显示字段级提示。
5. 点击故障或异常记录进入对应监管页面；未开放的外部系统入口显示不可用原因。
6. 地图、遥测、趋势以及故障/异常记录区域的数据更新时间可以不同，必须分别标注，不能使用单一时间覆盖全部模块。
7. 远程控制、急停、驾驶状态切换等高风险操作本期仅展示状态和处置入口，不提供直接执行按钮。

## 9 数据模型与接口要求

### 9.1 单车实时快照

实时快照包含车辆标识、车架号、网联编号、项目、坐标、定位时间、驾驶状态、信号强度、运行状态、补给状态、速度、档位、平台在线状态、SOC、剩余水量、垃圾箱状态、数据来源和采集时间。资源字段和来源独立业务数据遵循7.3～7.5节。

### 9.2 数据质量字段

每个数据域应支持：`source`（来源）、`collectedAt`（采集时间）、`receivedAt`（接收时间）、`quality`（正常/延迟/超时/无效）、`message`（异常说明）。

### 9.3 更新策略

真实接入时由后端或消息服务提供更新策略；前端不得自行推断数据仍然有效。当前使用静态演示数据验证字段及交互，不实现真实实时推送、过期判定、接口重试和权限审计。

## 10 高保真阶段范围
第一阶段实现统一基础字段、资源百分比、现有地图与下钻交互，并标明演示数据；真实接入与高级设备诊断不在本阶段范围。

## 11 验收标准

1. 运行监控Tab可从车辆总览进入，并保持当前车辆身份上下文。
2. 页面不重复展示车辆档案、运行总账和车辆总览完整可用性判定。
3. 接入实时数据后，能够展示单车数据质量、数据来源、数据采集时间、运行诊断字段，以及展示资源百分比与补给明细；不重复总览中的关键状态摘要。
4. 能够展示当前车辆位置、经纬度和定位时间；无效坐标不绘制误导性点位。
5. 能够展示与车辆能力匹配的基础遥测、资源和独立来源的任务信息，不适用字段不显示。
6. 故障和异常记录分别按各自上报时间倒序展示，并支持跳转车辆故障信息页、车辆异常记录页；不根据现有字段推断处理状态。
7. 趋势查询支持最近1小时、24小时、7天；无数据、延迟、超时、接口失败和部分字段缺失状态均有明确反馈。
8. 跳转车辆监管一张图、车辆运行数据、车辆故障信息和车辆异常记录时，能够带入当前车辆筛选条件。
9. 页面不提供远程控制、急停或驾驶状态切换等高风险直接操作。
10. 当前高保真阶段标明演示数据，字段、百分比和驾驶状态符合7.3节规则；1366×768和1920×1080视口下布局不重叠、不产生页面级横向溢出。
