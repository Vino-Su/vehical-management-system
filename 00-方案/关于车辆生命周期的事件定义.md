## 1 背景

在车辆的全生命周期管理中，会涉及到关于车务、业务等多个维度的事件，这些事件或大或小，共同组成了车辆的使用过程。出于管理角度，需要对这部分事件进行精简，选取其中重要的事件进行展示，形成类似于单个车辆的大事记，快速形成关于该车辆的概览。

为此，需要事先定义哪些事件属于车辆生命周期中的大事件


### 1.1 基本原则

1. **突出重要事项**：生命周期只展示能够代表车辆关键经历的业务结果，不展示全部操作日志和过程节点。
2. **以业务事实为准**：事件内容、时间和处理结果均以来源业务记录为准，不在生命周期页面单独维护。
3. **结果优先**：调度、维修、保养、保险和证照等流程以完成结果进入生命周期，普通中间节点不进入。
4. **避免重复展示**：同一业务事项在生命周期中只展示一次；同一次操作修改多个关键字段时合并展示。
5. **支持业务追溯**：用户可以从生命周期事件查看对应的业务详情，了解事件的完整信息。
6. **页面只读**：生命周期页面不提供事件新增、编辑和删除入口；内容修正应回到来源业务中完成。

## 2 事件类型

| 事件类型  | 事件名称    | 进入生命周期的条件                             | 信息来源          | 事件时间       | 是否展示 |
| ----- | ------- | ------------------------------------- | ------------- | ---------- | ---- |
| 建档    | 建档完成    | 车辆建档保存成功                              | 车辆建档          | 建档时间       | 是    |
| 信息变更  | 关键信息变更  | VIN 码、车牌号、固定资产编码、资产属性等关键字段发生实际变化并保存成功 | 车辆档案 - 变更日志   | 操作时间       | 是    |
| 维保事件  | 维修完成    | 维修记录或工单进入“已完成”状态                      | 维修记录/维修工单     | 维修完成时间     | 是    |
| 维保事件  | 保养完成    | 保养记录或工单进入“已完成”状态                      | 保养记录/保养工单     | 保养完成时间     | 是    |
| 故障    | 故障上报    | 车辆故障信息被系统接收并形成有效故障记录                  | 车辆故障信息        | 故障上报时间     | 是    |
| 异常事件  | 车辆异常    | 当前不进入生命周期                             | 车辆异常记录        | —          | 否    |
| 调度流转  | 调度完成    | 调度任务进入“已完成”，且当前车辆交接结果为“已交接”           | 调度任务及单车交接记录   | 当前车辆确认交接时间 | 是    |
| 合规事件  | 保险办理完成  | 保险业务办理完成并形成有效记录                       | 保险记录          | 保险办理完成时间   | 是    |
| 合规事件  | 证照办理完成  | 证照业务办理完成并形成有效记录                       | 证照记录          | 证照办理完成时间   | 是    |
| 风险事件  | 违章记录    | 形成有效违章记录                              | 违章记录          | 违章发生时间     | 是    |
| 风险事件  | 事故记录    | 形成有效事故记录                              | 事故记录          | 事故发生时间     | 是    |
| 费用产生  | 费用记录    | 不作为独立事件，相关金额随对应业务事件展示                 | 费用记录          | —          | 否    |
| SIM 卡 | SIM 卡更换 | 当前不进入生命周期                             | SIM 卡管理       | —          | 否    |
| 退出处置  | 车辆报废    | 车辆状态变更为“已报废”                          | 退出管理/车辆状态变更日志 | 状态变更时间     | 是    |
| 退出处置  | 车辆处置    | 车辆状态变更为“已处置”                          | 退出管理/车辆状态变更日志 | 状态变更时间     | 是    |

说明：

- “是否展示”为“否”的业务不进入生命周期，不采用生成后再隐藏的方式。
- 保险、证照、违章、事故、退出管理等模块的业务口径尚未完整定义时，以第 7 节待确认事项为准。

## 3 页面共性展示内容

生命周期页面以时间线形式展示车辆大事记。每条事件根据业务类型展示以下内容：

- **事件名称**：说明发生了什么，例如“车辆维修完成”。
- **事件时间**：采用业务实际发生时间，不使用信息录入时间替代。
- **事件摘要**：说明本次事件的关键结果，例如车辆由哪个项目调度至哪个项目。
- **业务信息**：根据事件类型展示工单编号、修改前后值、故障码、金额等必要内容。
- **操作人或信息来源**：有明确操作人的事件展示操作人；车辆或外部系统上报的信息展示来源。
- **查看详情**：来源业务存在详情页面时，提供对应的查看入口。

没有内容的非必需字段不在页面占位展示，避免出现大量无业务含义的“—”。

## 4 各类事件详细定义

### 4.1 建档

- **展示条件：** 车辆建档保存成功；保存失败或取消保存不展示。
- **信息来源：** 车辆建档记录。
- **事件时间：** 建档时间。
- **事件标题：** `车辆完成建档`。
- **事件摘要：** `车辆由{建档人}完成建档`；建档人为空时展示来源系统。
- **展示字段：** 事件类型、建档时间、建档人。
- **来源详情：** 进入当前车辆的车辆档案。

### 4.2 信息变更

- **展示条件：** 车辆档案保存成功，且关键字段的修改前后值不一致。
- **信息来源：** 车辆档案变更日志。
- **首期关键字段范围：** VIN 码、车牌号、固定资产编码、资产属性。
- **事件时间：** 变更日志的操作时间。
- **事件标题：** `车辆关键信息发生变更`。
- **事件摘要：** 单字段变更展示“{字段名称}由{修改前}变更为{修改后}”；同一次保存修改多个关键字段时，聚合为一条事件并逐项展示。
- **展示字段：** 事件类型、修改字段、修改前、修改后、操作人、操作时间。
- **来源详情：** 进入当前车辆的变更日志，并定位到对应操作记录。

### 4.3 维保事件

#### 4.3.1 维修完成

- **展示条件：** 维修记录或维修工单进入“已完成”状态；待处理、处理中、已取消等状态不展示。
- **信息来源：** 维修记录/维修工单。
- **事件时间：** 维修完成时间。
- **事件标题：** `车辆维修完成`。
- **展示字段：** 事件类型、子类型（维修）、工单编号、当前节点、完成时间、结算金额。
- **来源详情：** 进入对应维修记录或维修工单详情。

#### 4.3.2 保养完成

- **展示条件：** 保养记录或保养工单进入“已完成”状态；待处理、处理中、已取消等状态不展示。
- **信息来源：** 保养记录/保养工单。
- **事件时间：** 保养完成时间。
- **事件标题：** `车辆保养完成`。
- **展示字段：** 事件类型、子类型（保养）、工单编号、当前节点、完成时间、结算金额。
- **来源详情：** 进入对应保养记录或保养工单详情。

维保事件只在维修或保养完成后进入生命周期，页面不展示未完成工单的过程节点。“当前节点”保留来源工单完成时的节点名称，正常情况下应为“已完成”。

### 4.4 故障

- **展示条件：** 车辆上报的故障信息被系统接收并形成有效故障记录。
- **信息来源：** 车辆故障信息。
- **事件时间：** 故障上报时间。
- **事件标题：** `车辆上报故障：{故障定义}`。
- **展示字段：** 事件类型、故障码、故障定义、故障上报时间。
- **来源详情：** 进入车辆故障信息详情。
- **补充说明：** 同一故障记录不重复展示；同一故障重复上报时是否合并，沿用车辆故障信息模块的业务口径。

### 4.5 调度记录

- **展示条件：** 调度任务进入“已完成”状态，且当前车辆的交接结果为“已交接”。
- **不展示场景：** 调度申请、出库、待交接等中间状态不展示；当前车辆交接结果为“拒绝接收”时不展示项目流转完成事件。
- **信息来源：** 调度任务及当前车辆的单车交接记录。
- **事件时间：** 当前车辆确认交接时间。
- **事件标题：** `车辆完成项目调度`。
- **事件摘要：** `车辆由{调度前项目}调度至{调度后项目}`。
- **展示字段：** 事件类型、任务编号、调度前项目、调度后项目、调度完成时间。
- **来源详情：** 进入对应调度任务详情，并定位当前车辆。

### 4.6 合规事件

#### 4.6.1 保险办理完成

- **展示条件：** 保险业务办理完成并形成有效记录。
- **信息来源：** 保险记录。
- **事件时间：** 保险办理完成时间。
- **事件标题：** `车辆保险办理完成`。
- **展示字段：** 事件类型、子类型（保险）、业务单号、完成时间。
- **来源详情：** 进入对应保险记录详情。
- **补充说明：** 续保属于新的保险办理事项，应作为新的生命周期事件展示。

#### 4.6.2 证照办理完成

- **展示条件：** 证照业务办理完成并形成有效记录。
- **信息来源：** 证照记录。
- **事件时间：** 证照办理完成时间。
- **事件标题：** `车辆证照办理完成`。
- **展示字段：** 事件类型、子类型（证照）、证照类型、业务单号、完成时间。
- **来源详情：** 进入对应证照记录详情。
- **补充说明：** 同一车辆的不同证照分别作为独立事件展示。

### 4.7 风险事件

#### 4.7.1 违章记录

- **展示条件：** 形成有效违章记录。
- **信息来源：** 违章记录。
- **事件时间：** 违章发生时间，不使用数据录入时间替代。
- **事件标题：** `车辆发生违章`。
- **展示字段：** 事件类型、子类型（违章）、业务记录编号、发生时间、违章摘要。
- **来源详情：** 进入对应违章记录详情。

#### 4.7.2 事故记录

- **展示条件：** 形成有效事故记录。
- **信息来源：** 事故记录。
- **事件时间：** 事故发生时间，不使用数据录入时间替代。
- **事件标题：** `车辆发生事故`。
- **展示字段：** 事件类型、子类型（事故）、业务记录编号、发生时间、事故摘要。
- **来源详情：** 进入对应事故记录详情。

### 4.8 退出处置

#### 4.8.1 车辆报废

- **展示条件：** 车辆状态由非“已报废”变为“已报废”。
- **信息来源：** 退出管理记录；退出管理尚未接入时，取车辆状态变更日志。
- **事件时间：** 状态变更时间。
- **事件标题：** `车辆已报废`。
- **展示字段：** 事件类型、子类型（报废）、变更前状态、变更后状态、报废时间、操作人、来源单号。
- **来源详情：** 优先进入退出管理详情；没有退出管理记录时进入车辆变更日志。

#### 4.8.2 车辆处置

- **展示条件：** 车辆状态由非“已处置”变为“已处置”。
- **信息来源：** 退出管理记录；退出管理尚未接入时，取车辆状态变更日志。
- **事件时间：** 状态变更时间。
- **事件标题：** `车辆已处置`。
- **展示字段：** 事件类型、子类型（处置）、变更前状态、变更后状态、处置时间、操作人、来源单号。
- **来源详情：** 优先进入退出管理详情；没有退出管理记录时进入车辆变更日志。

车辆先报废、后处置时，应分别保留“车辆已报废”和“车辆已处置”两条事件；车辆直接变为“已处置”时，只记录实际发生的处置事件，不补造报废事件。

## 5 不纳入生命周期的记录

| 记录类型         | 处理方式                            | 原因                            |
| ------------ | ------------------------------- | ----------------------------- |
| 车辆异常事件       | 不进入生命周期，仍在车辆异常记录中查询             | 异常事件数量多、持续时间短，当前未定义进入大事记的筛选条件 |
| 独立费用记录       | 不作为独立事件进入生命周期；维修、保养等事件可展示对应结算金额 | 避免同一业务事项产生业务事件和费用事件两条重复记录     |
| SIM 卡更换记录    | 不进入生命周期，仍在 SIM 卡管理中查询           | 当前不属于车辆大事记范围                  |
| 非关键字段修改      | 仅写入车辆变更日志                       | 不影响车辆大事记，避免生命周期被普通编辑记录淹没      |
| 未完成或已取消的维保工单 | 不进入生命周期                         | 当前只展示维修、保养完成结果                |
| 调度中间节点       | 不进入生命周期                         | 当前只展示车辆实际完成项目流转的结果            |

后续如需把严重异常、SIM 卡停机等纳入生命周期，应先明确进入条件、页面内容和信息来源，再补充到本文档中。

## 6 数据与页面规则

### 6.1 数据口径

1. 生命周期展示内容以来源业务记录为准，不在生命周期页面单独维护另一套业务信息。
2. 来源业务记录被修正时，生命周期中同步展示修正后的内容，不重复增加一条相同事件。
3. 来源业务记录被撤销、作废或删除后，对应事件不再作为有效大事记展示。
4. 同一业务事项只展示一次，不因重复接收数据而出现多条相同事件。
5. 来源模块尚未建设或数据尚未接入时，不使用模拟数据代替正式事件。

### 6.2 页面规则

1. 生命周期事件仅在“车辆详情 - 生命周期”中展示，默认按事件时间倒序排列。
2. 每条事件至少展示事件标题、事件时间和事件摘要；其他字段按照第 4 节各事件定义展示。
3. 来源业务存在详情页面时，提供“查看详情”入口；尚无详情页面时不展示空入口。
4. 用户有来源业务查看权限时可以进入详情；无权限时仍可查看生命周期摘要，但不提供可点击入口，并提示“无权查看来源详情”。
5. 生命周期页面为只读页面，用户不能直接修改或删除事件。

## 7 待确认事项

以下事项仍缺少完整的业务定义，需要在相关模块设计或数据接入前确认：

| 待确认项      | 需要确认的产品口径                           | 影响事件      |
| --------- | ----------------------------------- | --------- |
| 关键信息范围    | “资产属性”具体包含哪些字段，是否还有其他必须进入大事记的车辆身份字段 | 关键信息变更    |
| 故障重复上报    | 同一故障持续或重复上报时，是合并展示还是按每次故障分别展示       | 故障上报      |
| 维修、保养完成   | 哪个业务节点代表正式完成，结算金额未产生时是否先展示事件        | 维修完成、保养完成 |
| 保险办理完成    | 哪个业务节点代表办理完成，续保是否始终作为一条新事件          | 保险办理完成    |
| 证照办理完成    | 纳入哪些证照类型，哪个业务节点代表办理完成               | 证照办理完成    |
| 违章、事故有效记录 | 录入后即进入生命周期，还是需要经过确认或审批后进入           | 违章记录、事故记录 |
| 退出管理来源    | 报废和处置是否均有独立的业务详情，以及没有退出流程时如何展示来源    | 车辆报废、车辆处置 |
| 历史展示范围    | 功能上线后展示车辆全部历史事件，还是只展示指定日期之后的事件      | 全部事件      |

## 8 验收口径

1. 第 2 节标记为“是”的事件满足展示条件后，能够在对应车辆的生命周期中出现。
2. 第 2 节标记为“否”的记录不会出现在生命周期中。
3. 每条事件的名称、时间、摘要和业务字段符合第 4 节定义，且信息与来源业务一致。
4. 信息变更只展示约定的关键字段，同一次操作修改多个关键字段时合并为一条事件。
5. 维修、保养仅在完成后展示，未完成和已取消记录不进入生命周期。
6. 调度仅在任务完成且当前车辆交接结果为“已交接”时展示；拒绝接收的车辆不展示调度完成事件。
7. “已报废”和“已处置”分别展示；车辆直接变为“已处置”时不补充未实际发生的报废事件。
8. 同一业务事项不会在生命周期中重复展示。
9. 存在来源详情且用户有权限时，可以从生命周期进入对应业务详情；无权限或暂无详情页面时的展示符合第 6.2 节规则。
