# 车辆管理系统

## 项目简介

车辆管理系统是一个面向企业车辆资产管理的前端原型系统，涵盖车辆全生命周期管理。系统采用纯 HTML/CSS/JavaScript 实现，可作为前端高保真原型或后续前后端分离开发的基础模板。

系统采用“顶部一级模块 + 左侧二三级导航”结构：车辆管理、运行监管、维保管理、合规与风险、费用管理、退出管理、数据分析、系统管理八个一级模块位于顶部；侧栏随一级模块切换，并支持收起为 64px 图标栏。

业务页右上角统一展示当前用户名称，支持长名称省略与完整提示；点击名称展开账号菜单。“退出登录”为占位按钮，点击提示暂未开放，保留当前页面与数据；顶部不展示通知占位图标。

## 功能模块

### 1. 车辆建档
- **列表页**：支持多维度查询筛选（车架号、车牌号、车型名称、车辆状态等），分页展示车辆建档数据，支持批量导入、单条录入、数据导出。
- **新增页**：新车信息录入表单，涵盖车辆基础信息、归属信息、车辆照片、行驶证信息、车型信息、硬件与SIM关联、车辆功能配置（含绑定对讲机）、车辆标签及备注；资产属性包含运营车辆-气动，车型名称与实际版本、车型参数联动。录入页不提供车辆状态、车型编码，不展示车载WIFI密码和维护信息分组。
- **详情页**：车辆档案详情展示（预留入口，联动资产管理模块）。

### 2. 车辆资产管理
- **列表页**：车辆资产全量列表，支持车辆分配、编辑、删除、导出等操作，多条件组合查询；支持从车型管理页带参进入（`?modelName=…&modelVersion=…`）自动按车型版本筛选，「车型版本」查询下拉按列表实际数据去重生成；支持跨页勾选车辆后批量导出二维码，每辆车生成以 VIN 命名的 PNG 图片并打包下载为 ZIP，二维码内容为车辆 VIN，与详情页二维码一致；详情页二维码弹窗同时展示 VIN 码、车牌号和网联编号。
- **详情页**：单车360度档案，采用“车辆总览、运行监控、车辆档案、业务记录、生命周期、变更日志”六个一级Tab；车辆全局信息区与Tab吸顶固定；车辆总览由运行总账指标条（累计里程、累计费用、车龄，费用附统计口径说明）与当班决策看板（作业可用性、实时运行、当班保障、健康与损耗、合规与风险、当前提醒）构成，直接展示关键状态数值和处置入口；运行监控定位为单车实时诊断与下钻工作台，聚焦数据状态、Leaflet位置与轨迹、运行遥测、安全与系统诊断、资源与设备明细、任务关联、趋势、故障/异常原始记录和关联入口，并与监管一张图复用共享车辆快照；车辆档案提供查看态/编辑态共用的分组目录快速定位；业务记录下汇总调度、售后维保、BOM、合规与风险和费用；生命周期以只读时间线汇总建档、关键信息变更、完成态维保与调度、故障、合规、风险及退出处置事件，支持分类/时间筛选和来源详情追溯。运行监控详细设计见《车辆运行监控PRD》。

资产列表行内“编辑”入口默认打开车辆详情的“车辆档案”Tab并直接进入编辑态；“详情”入口默认显示车辆总览。
车辆档案中的“维护信息”统一展示创建人、创建时间、创建方式、更新人、更新时间，查看态和编辑态均只读；保存成功后刷新更新信息。
车辆详情“车辆基础信息”的车载WIFI密码由接口获取，查看态和编辑态均只读，缺失时显示“—”，不参与表单保存；本次原型不实现真实接口。
车辆详情“车辆功能配置”支持查看与编辑绑定对讲机，枚举值为“有、无”。
车辆详情“车辆档案”的查看态、编辑态及档案目录，与车辆建档“单个录入”统一按“摄像头图片配置 → 车辆功能配置 → 平行驾驶配置”的顺序展示。

### 2.1 设备管理
- **设备台账页**：独立维护 T-Box、ADU、OBU、DTU、视频盒子等车端网联终端，字段与车辆档案「硬件信息」表对齐（设备名称、设备类型、设备识别码、是否有SIM卡、IMSI、状态、厂商/型号）；采用「左栏分组管理 + 右栏台账表格」工作台布局：左栏支持按设备识别码检索、按设备类型/车辆VIN码/项目三种维度分组浏览，分组可折叠展开并显示组内台数，缺少当前分组属性的设备归入「无分组」并固定置末，顶部「全部」默认选中、组内设备按识别码排序（按「车辆VIN码」分组时分组标题仅展示 VIN 码、不附带车牌）；点击分组行选中该分组、点击行首箭头仅折叠展开、点击设备定位到单台设备，右栏表格随左栏选择范围收敛；右栏仅保留是否有SIM卡、状态两项筛选（设备类型、车辆、归属项目由左栏承担），支持设备主数据新增/编辑、分页、导出；行内「详情」跳转设备详情页。新增设备保存后自动定位到该设备并清空左栏检索，编辑与绑定保存后保留当前浏览范围并刷新左栏分组与计数。
- **设备详情页**：二级页面（替代原抽屉样式），展示设备信息、当前绑定（车辆VIN码、是否有SIM卡、IMSI）与设备变更日志，顶部提供「返回列表 / 编辑设备 / 维护绑定」入口。设备变更日志为只读字段级事件表（操作类型、修改字段、修改前、修改后、操作人、操作时间），列与对齐口径对齐车辆资产详情「变更日志」Tab：设备主数据按变化字段逐项记录（修改字段严格沿用设备字段名），绑定关系按「车辆VIN码」「IMSI」两项分别记录且只存纯 VIN / 纯 IMSI，解绑侧留空显示「—」，按操作时间倒序、默认每页 10 条、无记录展示空态；保存后无任何字段变化时不写入日志。变更日志仅在设备侧留痕，不写入车辆资产详情的变更日志。台账与详情页的车辆 VIN 码、IMSI 均为超链接，分别跳转车辆资产详情页与 SIM 卡详情页。
- **绑定关系维护**：支持从设备台账或详情页维护设备与车辆、SIM 卡的当前绑定关系，并保留绑定/解绑/更换等历史记录；同一张 SIM 卡同一时间只能绑定一个设备。本期暂不展示设备在线、最近上报和健康诊断等动态信息。
- **数据来源**：设备/车辆/SIM 演示数据统一维护在 `03-高保真页面/components/fleet-data.js`，由设备管理与 SIM 卡管理两侧页面共用；SIM 卡的绑定字段（VIN 码、车牌号、归属项目、硬件类型、硬件识别码）由设备台账的绑定关系派生。
- 详细设计见《设备管理PRD》。

### 3. 车型管理
- **列表页**：车型主数据管理，支持可折叠展开的版本子列表；车型可暂时没有版本。两级操作文案统一带层级后缀：车型行提供车型详情、编辑车型、新建版本、删除车型入口，版本行提供版本详情、编辑版本、新建版本、删除版本入口（内外操作列同宽 280px，按钮统一左对齐）。版本列表展示车型版本、车辆型号、整车厂商、创建人、创建时间、更新人、更新时间。查询区默认展示 4 个条件、可展开全部 11 个，收起/展开复用公共组件 `filter-component.js`（`data-visible-count="4"`，legacy 自动绑定）。
- **新增页**：车型信息必填，版本信息可选；支持创建车型后从列表快捷补充首个版本。
- **车型详情页**：独立展示车型公共信息及关联版本；关联版本区字段与列表页版本子表一致（车型版本、车辆型号、整车厂商、创建人、创建时间、更新人、更新时间、操作），操作栏同为版本详情、编辑版本、新建版本、删除版本；支持编辑车型（车型级字段的唯一编辑入口，车型来源、编码头只读）、无版本车型快捷添加版本，车型删除仅校验是否仍存在版本（引用锚定在版本维度，故不做车辆引用校验）；下方「变更日志」区展示本车型的**车型级**变更记录，只读、按操作时间倒序、不提供导出。
- **版本详情页**：车型公共信息只读；编辑态「车型信息」分组只读置灰展示（不可编辑、不采集、不校验，附 12px 辅助提示），仅版本级字段可编辑（车型级字段统一由车型详情页维护，必填校验仅版本级）；变更日志仅展示本版本的**版本级**记录（车型级变更记入车型详情页），车型详情页与版本详情页日志相互隔离；删除版本前校验该版本的关联车辆数，被引用时阻断并仅提示车辆台数，可通过「查看车辆」跳转车辆资产列表（自动按车型名称 + 车型版本筛选）。
- **变更日志规则**：按字段作用域记录，与操作入口页面无关——车型级字段（车型来源、车型名称（中/英）、车型别名、用途分类、车型编码、编码头）记入车型日志，版本级字段（车型版本、车辆型号、动力类别、排放标准、主要参数信息、其他信息）记入版本日志；一次保存按变更字段拆条并共享同一操作时间；无实际字段变化不记录，载重分类等联动自动计算字段不单独记录；本期仅记录修改行为（删除/新增暂不记录）。数据由 `components/vehicle-model-store.js` 的 `changeLogs` 承载（`appendChanges` 写入、`logs` 查询）。
- **删除规则**：按对象唯一校验、校验项互不交叉——车型删除只校验「是否仍存在版本」，无版本即可删除；版本删除只校验「关联车辆数」，>0 一律不可物理删除（实时引用口径，不做连带删除、不做快照兜底）。引用锚定在「车型版本」维度（车辆建档必选车型名称 + 车型版本），故车型可删时必然不存在车辆引用。版本删除阻断弹窗仅展示引用车辆数量（不含车牌明细），提供「查看车辆」入口跳转车辆资产列表并自动回填「车型名称（中）」+「车型版本」筛选条件，筛选行数与弹窗台数一致。本期删除操作不记录变更日志。
- **新建版本页**：分两类入口语义——车型级入口（列表车型行 / 无版本空状态 / 车型详情页顶部操作栏）仅继承车型信息、版本参数留空；版本级入口（列表版本行 / 版本详情页 / 车型详情页关联版本行）以指定版本为模板复制参数后创建新版本。

### 4. 车辆标签管理
- **标签管理列表页**：采用「左标签列表 + 右车辆明细」工作台布局。左栏以两级结构（标签组 + 子标签）展示标签并区分公有/私有分组，支持按标签名称检索、新建标签组/标签、编辑、删除与展开收起，鼠标悬停可将「数量」切换为操作入口；右栏展示当前标签（或标签组聚合）下的关联车辆明细，支持车架号、车型名称、车牌号、车辆状态查询（归属项目仅筛选车辆，不影响标签），子标签车辆列表展示打标时间与打标人，并提供移入车辆、批量移出与导出。
- **车辆资产管理联动**：资产管理列表页支持按标签筛选、标签列展示、批量打标签/移出标签；批量移出弹窗按车辆展示已有标签并默认全部勾选，取消勾选后点击确定移出，保持勾选的标签保留；详情页基础信息支持单车标签管理。
- 标签与车辆为多对多关系，不影响车辆状态与归属项目等既有业务字段。
- 移入车辆弹窗默认仅显示未关联当前标签的车辆，支持切换“显示全部车辆”；已关联车辆整行置灰，复选框选中且禁用，不展示“已添加”标识。本次已选数量仅统计新选车辆，支持分页与跨页保留选择，全选仅作用于当前页可移入车辆。
- 标签组与子标签车辆列表均支持跨页勾选；普通数据导出仅包含当前页勾选车辆，无勾选时确认后导出当前筛选结果的全部车辆为 XLSX。标签组按车架号去重，导出包含当前组内的全部所属子标签；组视图勾选仅用于导出，移入/移出仍在具体子标签内操作。
- 详细设计见《标签管理PRD》。

### 5. 车辆调度管理
- **可用车辆库列表页**：展示在库-闲置可调出车辆，支持多条件查询、新增调度申请、导出。
- **调度记录管理列表页**：调度任务全流程管理（新建/编辑/提交/撤回/再次提交/删除/导出），支持出库审批、交接审批。
- **调度申请详情页**：三环节步骤条（申请→出库→交接）与流程日志，按状态提供对应操作按钮。
- 详细设计见《调度管理PRD》。

### 5.1 车辆运营
- **用车记录**：位于“运行监管 > 车辆运营”（侧栏排在“异常事件”之后），查询区与表格参照车辆资产列表；列表在“关联车牌号”前展示车架号与网联编号（同一车辆取值一致）；查询区支持司机、车牌号、车架号、网联编号模糊匹配，首行按空间展示，放不下的条件默认收起并可展开；支持跨页选择、详情查看、分页和导出 CSV。详见《车辆运营-用车记录PRD》。

### 6. SIM 卡管理
- **SIM 卡台账列表页**：支持 SIM 卡、套餐、用量、车辆及终端等多条件筛选，并支持选择数据或按当前条件导出；行内提供「详情」与「信息维护」入口。
- **SIM 卡详情页**：展示基本信息、计费周期、终端信息、日/月流量统计及可分页的历史绑定记录；顶部提供「信息维护」入口。
- **信息维护弹窗**：由台账行内或详情页顶部打开，样式与设备管理「维护绑定关系」弹窗统一。车辆与硬件识别码均使用可搜索选择器（按车牌号/VIN 码/项目、硬件识别码/类型模糊匹配并高亮），车辆仅用于定位终端、不改变设备与车辆的绑定关系；已被其他 SIM 卡占用的硬件可见但置灰不可选并标注占用 IMSI；清空硬件即解绑。保存后关闭弹窗并新增一条绑定记录，同时写入该终端的设备变更日志。
- **数据口径**：SIM 卡的绑定字段统一由设备台账派生，与设备管理共用一份数据源（`components/fleet-data.js`），两侧台账不再各维护一份绑定关系。
- **SIM 卡流量明细页**：左侧支持按运营商、套餐或项目分组检索 SIM 卡，右侧按单卡查询日/月流量，支持分页选择与导出。
- **车辆流量明细页**：左侧支持按项目或车型分组检索车辆，右侧汇总车辆关联全部 SIM 卡的日/月流量，支持分页选择与导出。
- 详细设计见《SIM卡管理PRD》。

### 7. 能耗费用台账
- **加油费用明细台账**：支持按加油时间、车牌号、关联油卡、上报人筛选，展示油量、单价、金额、油卡余额、里程及凭证；支持新增、编辑、详情、变更记录、删除、导入导出与分页。
- **加水费用明细台账**：支持按加水时间、车牌号、上报人筛选，覆盖月付、现金及线上支付场景；支持新增、编辑、详情、变更记录、删除、导入导出与分页。
- **充电费用明细台账**：支持按充电开始时间、车牌号、上报人筛选，展示时长、度数、电费、服务费、金额、里程及充电明细；支持新增、编辑、详情、变更记录、删除、导入导出与分页。

### 8. 车辆实时监管
- **车辆监管一张图**：基于 Leaflet + OpenStreetMap 的车辆地图监管，默认按市聚合；地图右上角以搜索/筛选图标按需展开精确搜索和项目/区域/车型多选下拉筛选；左侧车辆列表、异常与故障两个 Tab 仅保留项目/车型/区域分组，并与地图条件联动；支持紧凑车辆详情弹窗、故障异常角标、原地图窗口内轨迹回放控制台和视频弹窗，轨迹回放可按日期、时段、车辆查询并支持播放暂停、倍速、拖动时间轴和状态联动。
- **车辆运行数据**：左侧按项目或车型分组查询并选择车辆，右侧按采集时间查看终端上报的位置、驾驶、车辆姿态、作业模式及在线状态数据，支持分页选择与导出。
- **车辆故障信息**：按车辆标识、项目、故障码和上报时间查询车辆主动上报的软硬件故障，支持分页选择与导出。
- **车辆异常记录**：展示策略规则触发的超时停靠、超速行驶和限行区行驶记录，支持组合查询、分页选择与导出。
- 详细设计见《车辆实时监管PRD》。
- 车辆资产详情页的单车运行监控边界、实时状态、位置、遥测、健康安全、趋势和告警下钻见《车辆运行监控PRD》。

### 9. 流量费用明细
- **流量费用明细页**：以车辆为主体、按月度展示流量费用，支持统计月份、车牌号、VIN 码与归属项目查询；列表展示关联卡数、当月用量、流量使用率、单位成本与流量费用并统计条数、车辆数、用量合计与费用合计；详情支持按 SIM 卡拆分下钻；导出支持选中或当前查询条件全部。
- 费用口径：单卡费用 = 该卡当月用量 × 所属流量池单位成本，单车费用为各卡费用之和，单车单位成本为加权平均值。
- 详细设计见《流量费用明细PRD》。

### 10. 单车费用管理
- **单车费用台账**：从“费用管理 > 单车费用管理”进入，沿用系统公共导航、筛选与分页；支持按日期、车牌号或 VIN 查询，以车辆为行展示加油、加水、充电、流量费用及合计，导出当前查询结果。
- 费用金额引用现有费用明细；点击单项金额可查看多条来源记录，单条记录可跳转到原费用页面并打开详情。页面仅展示台账，不增加统计卡片、占比图和趋势图。
- 当前为静态原型；能耗修改通过浏览器本地存储共享，流量费用按原月度核算结果关联；车辆详情“费用信息”仍待开放。
- 详细设计见《单车费用管理_PRD》。

## 使用方式

1. 克隆或下载本项目到本地。
2. 直接用浏览器打开根目录的 `index.html`（会自动跳转到 `03-高保真页面/index.html` 页面索引）。
3. 在页面索引中点击任意模块/页面即可预览。

> 说明：本系统为纯前端静态页面，数据为本地模拟数据，无需后端服务即可运行预览。
> 已适配 GitHub Pages：开启 Pages 后访问仓库根地址即可打开页面索引；所有页面均使用相对路径，可脱离服务器直接双击打开。

## 技术说明

- **技术栈**：HTML5 + CSS3 + 原生 JavaScript（无框架依赖，无任何 CDN / 外部资源）。
- **布局方案**：顶部固定 64px 一级模块导航；左侧二三级侧栏默认 224px、可收起至 64px；主内容区自动填充剩余空间。
- **公共组件**：见上方「公共组件」表。
- **UI 设计规范**：所有页面严格遵循 `.claude/UI_design_WEB.md`，包括设计令牌、字号层级、8px 间距体系、表格对齐规则、弹窗按钮布局等。
  - 注：该规范「技术栈」条款要求 Tailwind CSS v3，本项目实际采用**手写 CSS + 设计令牌变量**实现同等视觉与交互效果，以避免对既有页面的大规模重写；此为已知的有意偏离。
- **浏览器兼容**：推荐 Chrome / Edge 等现代浏览器；已在 1366×768 与 1920×1080 下验证。
